一直好奇一个问题：同样一台机器，直接跑 Debian 和装在 PVE 虚拟机里跑，CPU 性能到底差多少？虚拟化到底会不会"吃"掉算力？与其听别人说，不如自己测一把。于是我在 Debian 宿主机和 Proxmox VE（PVE）虚拟机里各跑了一轮 sysbench，单线程、同一套命令，公平公正。

## 测试方法

两边都用同一条命令，单线程跑 10 秒：

```bash
sysbench cpu --cpu-max-prime=20000 run
```

这条命令会让 CPU 反复计算 20000 以内的最大质数，10 秒内能完成的事件数就是它的成绩单。`--cpu-max-prime=20000` 把计算量固定住，两边跑出来的数据才公平可比。

- 宿主机：Debian 机器
- 虚拟机：Proxmox VE（PVE）里的虚拟机

## 结果对比

### CPU 速度（事件数/秒）

- Debian 宿主机：387.08
- PVE 虚拟机：387.91

PVE 高了约 0.83%，差距小到可以忽略。

### 总事件数

- Debian 宿主机：3872
- PVE 虚拟机：3880

10 秒内 PVE 多处理了 8 个事件，同样微不足道。

### 总时间

- Debian 宿主机：10.0013 秒
- PVE 虚拟机：10.0004 秒

差距 0.0009 秒，基本就是测试误差，连眨个眼的功夫都算不上。

### 延迟

| 指标 | Debian 宿主机 | PVE 虚拟机 |
| --- | --- | --- |
| 最小延迟 | 2.57 ms | 2.57 ms |
| 平均延迟 | 2.58 ms | 2.58 ms |
| 最大延迟 | 2.69 ms | 3.14 ms |
| 95% 延迟 | 2.57 ms | 2.57 ms |

最小延迟和 95% 延迟完全一致；PVE 的最大延迟略高（3.14 ms vs 2.69 ms），大概率是个别事件的波动，整体来看虚拟化几乎没给延迟"加税"。

### 线程公平性

| 指标 | Debian 宿主机 | PVE 虚拟机 |
| --- | --- | --- |
| 事件数（平均/标准差） | 3872.0000 / 0.00 | 3880.0000 / 0.00 |
| 执行时间（平均/标准差） | 10.0000 / 0.00 | 9.9988 / 0.00 |

两边的事件数、执行时间标准差都是 0，说明线程负载分配非常均匀，PVE 虚拟机的线程调度没有引入额外偏差，调度器很"听话"。

## 结论

两台机器的 CPU 性能几乎完全相同，PVE 虚拟机在事件处理速度和总事件数上反而略高一点点，但都不到 1%，完全可以认为是测试环境差异（系统负载、后台进程）造成的噪声。

在这个场景下，虚拟化对 CPU 算力的损耗基本可以忽略不计。所以别再被"虚拟机性能大打折扣"的说法吓到焦虑——至少纯 CPU 计算这块，现代虚拟化真的已经做到了"隐形"。

当然，这次测的只是纯 CPU 计算这一个场景，内存、磁盘、网络这些 IO 密集型的活儿，虚拟化会不会有损耗，那就是另一个故事了。

## 想测得更准？

1. 多跑几次取平均值，减少偶然误差
2. 加多线程、浮点运算等更复杂的场景，看综合性能
3. 对比两台机器的 CPU 型号、核心数、频率等硬件信息
