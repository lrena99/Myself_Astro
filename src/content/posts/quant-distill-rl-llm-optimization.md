# 量化 + 蒸馏 + 强化学习：我的 LLM 优化研究笔记

这篇是我的研究笔记，主题一句话：把量化、蒸馏和强化学习（RL）组合起来，在不大幅牺牲性能的前提下，把大模型的推理能力和效率都提上去。量化负责砍掉存储和计算成本，蒸馏负责把大模型的知识搬进小模型，再用大规模 RL 训练让它在复杂任务里更能打。我自己的实验观察是，量化蒸馏后的模型在推理任务上能和原始大模型掰手腕，同时计算资源消耗少一大截；而 RL 的加入，又让它在复杂推理和多任务场景里更上一层楼。

笔记的骨架很简单：先讲清楚为什么要做这件事，再把方法拆开看（GRPO、奖励模型、冷启动、蒸馏），接着是我照着 DeepSeek-R1 思路做的四阶段实操，最后聊一聊讨论和踩过的坑。来吧，一起看。

## 1 为什么做这件事

2024 年，OpenAI、Anthropic、谷歌这些机构在 LLM 上一路狂奔，一步步缩小着和通用人工智能（AGI）的差距。在这个背景下，后训练成了训练流程里不可或缺的一环——花更少的计算资源，把推理准确率提上去，还让模型跟社会价值观对齐、贴合用户偏好。

OpenAI 的 o1 系列靠拉长思维链（CoT）引入了"推理时间扩展"，在数学、编码、科学推理上进步明显。但怎么做好测试时扩展，至今还是研究界的大难题：过程奖励模型、强化学习、搜索算法都有人试过，可没有一个达到 o1 级别的通用推理性能。路倒是不少，就是没人真正走通。

转折点是 DeepSeek。他们用纯 RL 训练 DeepSeek-V3-Base，以 GRPO 为框架，在完全没有监督数据的情况下让模型自己长出推理能力。注意，是"完全没有监督数据"——不喂答案、不教思路，纯靠奖励信号自己摸索。几千步 RL 之后，DeepSeek-R1-Zero 在推理基准上追平了 OpenAI-o1-0912，这个成绩相当惊人。代价也很真实：可读性差、语言混杂，输出经常没法看。模型会了，但"会说人话"这件事还没学会。

于是 DeepSeek 又推出了 R1，思路是"先扶上马，再送一程"：先用几千条冷启动数据微调 base 模型，教它把话说清楚，再做面向推理的 RL；RL 快收敛时用拒绝采样造新的 SFT 数据，混合多领域监督数据重新训练。最后得到的检查点性能对齐 OpenAI-o1-1217。他们还进一步尝试把 R1 蒸馏进更小的密集模型——用 Qwen2.5-32B 做底座直接蒸馏，效果居然好过在它身上跑 RL。这说明更大的基础模型发现的推理模式，对提升小模型的推理能力至关重要。蒸馏出的 14B 模型比当时的开源 SOTA QwQ-32B-Preview 还强，32B 和 70B 直接刷新了密集模型推理基准的纪录，蒸馏后的 Qwen 和 Llama 系列模型也全部开源，人人都能拿来用。

这套框架里三个工具的分工很明确：量化解决"装得下"——把存储和计算成本压下来；蒸馏解决"学得会"——把大模型的知识搬进小模型；RL 解决"练得强"——让模型在复杂推理和多任务场景里更进一步。实验结果表明，经过量化和蒸馏的模型在推理任务中表现出与原始大模型相近的性能，同时显著减少计算资源消耗；强化学习的引入则进一步提升了模型在推理任务中的表现，尤其在复杂推理和多任务场景中。

总结下来就是：纯 RL 能解锁推理能力，但伴随可读性差、语言混杂的问题；蒸馏则是把小模型"喂大"的性价比路线，又快又省。我接下来的研究，就是基于量化和蒸馏的强化学习优化技术，到底怎么落地。一个想效率，一个想上限，两个都得抓住。

## 2 方法

方法部分按顺序拆四块：先看强化学习算法 GRPO 怎么算，再看奖励模型怎么给分、训练模板怎么约束输出，然后是一条完整的带冷启动的强化学习流水线，最后单独讲讲蒸馏这条性价比路线。每一块都是后面实操要用到的零件。

### 2.1 强化学习算法：GRPO

组相对策略优化（GRPO）的核心思想，是用一组采样输出来估计基线，这样就不需要和策略模型一样大的 critic 模型了。对每个问题，从旧策略采样一组输出，然后优化策略模型：

- **目标函数**：最小化策略模型与旧策略的比率乘奖励，加上 KL 散度正则项。比率告诉我们新策略比旧策略"进步"了多少，奖励告诉我们这个方向对不对，两者相乘就是前进的动力。直觉上可以这么理解：比率是步子，奖励是方向，KL 是刹车；
- **KL 散度**：衡量当前策略和参考策略差多远，防止模型跑飞。它像一根缰绳，拉住策略，不让它在奖励的诱惑下彻底失控；
- **优势计算**：用每组输出的奖励做标准化，让奖励分布更稳定。一组输出互相比较，谁比平均水平好谁就受鼓励，奖励的绝对大小不再重要，训练稳得多。

对每个问题都重复"采样一组输出 → 组内比较 → 更新策略"这个循环，策略就在一轮轮的循环里慢慢变强。标准化处理让奖励分布更稳定，不同问题之间的尺度差异也被拉平了。一句话总结：GRPO 用"组内比较"替代了庞大的 critic 模型，省内存又稳定，是 R1-Zero 能跑起来的引擎。

### 2.2 奖励模型

两条奖励线：

- **准确性奖励**：看回答对不对。数学这种有确定答案的问题，要求模型把最终答案放进特定格式（比如框起来）方便验证；编程题就让编译器按预定义测试用例给反馈。答对了有糖吃，答错了没得吃，简单粗暴。数学和编程天然适合规则化验证，奖励给起来最省心；
- **格式奖励**：要求模型把思考过程包在特定标签里（比如 `<think>` 和 `</think>`），规范输出格式。相当于给模型立规矩：心里话写在哪、答案写在哪，都得按套路来，不许乱。

两条线各管一件事：准确性奖励管"对不对"，格式奖励管"好不好看"。前者逼模型把本事练出来，后者逼它把话说清楚——R1-Zero 最大的毛病就是语言混杂、输出没法看，格式奖励就是专门来治这个的。两条奖励线加起来，模型既知道"做什么"，也知道"怎么说"，训练信号才算完整。

### 2.3 训练模板

一个简单的模板，让模型先输出推理过程再给答案：

```text
User: prompt
Assistant: <think>推理过程</think><answer>答案</answer>
```

训练时把具体问题替换进 `prompt` 就行。模板虽小，却是整个训练流程的地基——模型的每一步输出都被它框得明明白白，后面所有花活都在这块地基上盖。没有它，模型的输出就乱套了，所有奖励和格式要求也失去了落点。

### 2.4 带冷启动的强化学习

这一整套流程不是凭空设计的，而是把 R1 论文里"先扶正、再强化、后补全、最后收尾"的四步节奏拆开揉碎，每一步都有明确要解决的问题。

#### 冷启动

先收集少量长链推理数据微调基础模型，作为 RL 的起点。没有这一步，模型就像一张白纸直接上考场，RL 早期训练很容易不稳定。生成冷启动数据有三种路子：用长 CoT 示例做少样本提示，让模型照着样子学；直接让模型生成带反思和验证的详细答案；收集模型输出后人工标注后处理，把脏活累活交给人类。这三条路子也可以混着用：先让模型自己生成，再人工挑一挑、改一改，数据质量就有保障了。目标是提高可读性和推理能力——设计"推理过程 + 总结"的可读格式，过滤掉不合格输出，让 RL 从一条干净的起跑线出发。

#### 推理导向 RL

在冷启动微调后的模型上，用和 R1-Zero 一样的 RL 流程，专攻编程、数学、科学、逻辑推理这些推理密集型任务。这个阶段最头疼的是语言混合：思维链里中文英文甚至别的语言混成一锅粥。针对这个问题引入语言一致性奖励——统计思维链里目标语言词的比例，比例越高奖励越高，再和准确性奖励相加作为最终奖励。代价是消融实验显示性能会略降，但对话可读性符合人类偏好，值得。

#### 拒绝采样 + SFT

RL 收敛后，用拒绝采样从 checkpoint 生成推理提示和轨迹扩数据集，过滤掉语言混合、超长段落、代码块，只留正确输出，相当于给数据集做一轮大扫除；非推理任务（写作、事实问答、自我认知、翻译）用自动数据生成加复用已有的 SFT 数据集，部分非推理任务还会先生成一条潜在的思维链再作答。最后攒出约 800k 样本，对基础模型做两轮微调。

#### 全场景 RL

组合奖励信号加多样化提示分布，让模型在推理之外也把"有用"和"安全"捡起来。推理数据用规则化奖励引导数学、编程、逻辑；通用数据用奖励模型捕捉复杂场景的人类偏好，因为通用任务没有标准答案，只能靠人类偏好来当尺子。安全性上全面评估输出——推理过程和总结都查，识别并削减风险、偏见、有害内容。到这里，一个能推理、懂礼貌、守规矩的模型就成形了。

### 2.5 蒸馏：给小模型开外挂

生成 800k 样本直接对开源小模型做 SFT，把推理能力迁移过去。基础模型选 Qwen2.5-Math 系列（1.5B / 7B / 14B / 32B）、Llama-3.1-8B、Llama-3.3-70B-Instruct（3.3 的推理略强于 3.1），从 1.5B 到 70B 覆盖了不同量级。蒸馏迁移的是大模型已经长出来的推理能力本身，而不是让模型从零开始重新长一遍。关键一步：只做 SFT 不加 RL——这样才能干净地展示蒸馏本身的效果，不让 RL 来抢功。效果前面说过，14B 打赢当时的开源 SOTA，32B、70B 破纪录，小模型靠"抄作业"抄出了大出息，蒸馏省下的也不只是训练时间，还有探索推理模式的那一大笔试错成本。

## 3 我的实操：四阶段复现 DeepSeek-R1 思路

受 R1-Zero 成果启发，我在实际场景里遇到两个真问题：其一，能不能用少量高质量数据做冷启动，进一步提升推理性能或加快收敛速度？其二，怎么训练出一个既能生成清晰连贯思维链（CoT）、又有强大通用能力的用户友好型模型？前一个问题关于"起步"，后一个问题关于"落点"，恰好对应训练流程的头和尾。为了搞清楚这两个问题，我参考 DeepSeek-R1 的流程，设计了四个阶段，一个一个来。

### 3.1 冷启动

和 R1-Zero 不同，我担心 RL 在基础模型早期冷启动阶段不稳定，所以先收集少量长思维链数据微调，作为初始 RL 智能体——这一步相当于给 RL 找了个靠谱的教练，而不是让它在真空中瞎练。收集手段试了好几种：以长思维链作为示例做少样本提示、直接让模型生成经过反思与验证的详细答案、以可读格式收集输出再通过人工标注后处理优化结果。最终收集了几千条冷启动数据，对 base 模型进行微调，作为强化学习的起点。经过对比，我发现冷启动有两个明显优势：

- **可读性**：R1-Zero 的输出经常混着多种语言、缺 Markdown 格式，用户根本没法看。我的冷启动数据设计成"推理过程 + 总结"的结构化格式：推理过程是对查询的思维链，总结用来概括推理结果，输出格式定义为特殊标记包着 `<推理过程>`、特殊标记包着 `<总结>`，每个回复结尾都有总结，再过滤掉难读的回复；
- **潜力**：结合人类先验精心设计冷启动模式，实测性能优于 R1-Zero 路线，推理能力显著提升。有了人类先验"指路"，模型起步就站在了正确的坡上，而不是在奖励信号里瞎撞。迭代式训练对推理模型来说确实是更优解。

### 3.2 面向推理的 RL

在冷启动微调后的模型上跑大规模 RL，聚焦编码、数学、科学、逻辑推理。训练中观察到思维链经常语言混合（尤其提示词多语言时），于是引入语言一致性奖励——思维链中目标语言词的比例。消融显示性能略降，但符合人类偏好、内容更可读。最终奖励 = 推理准确性 + 语言一致性奖励，模型一边要答对题，一边要把话说成目标语言，两件事一起打分，就这样在微调后的模型上一直训到推理任务收敛为止。

### 3.3 拒绝采样 + SFT

RL 收敛后，用 checkpoint 收集下一轮的 SFT 数据。这一阶段和冷启动不同，必须纳入其他领域数据来提升写作、角色扮演等通用能力。推理数据通过拒绝采样生成轨迹：前一阶段只纳入能用基于规则的奖励评估的数据，这一阶段扩展了用生成式奖励模型判别的数据——把真实值和模型预测喂给大模型判断；同时过滤语言混合、长段落、代码块，每个提示采样多个回复只留对的。非推理数据复用大模型的 SFT 流程——写作、事实问答、自我认知、翻译这类任务没有标准答案，只能靠自动生成加复用现成的 SFT 数据来补，简单的查询（比如"你好"）不生成思维链，直接答。

### 3.4 全场景 RL

第二阶段 RL 主打有用性和无害性，同时保持推理能力，让模型进一步符合人类偏好。推理数据用规则化奖励引导数学、代码、逻辑，遵循 R1-Zero 里概述的方法，效果不错；通用数据用奖励模型抓人类偏好，偏好对分布和训练提示沿用大模型那套流程。评估分两头：有用性只看最终总结，避免干扰底层推理，评估强调回复对用户的实用性和相关性，用户满意度也跟着上来了；无害性则评估整个回复——推理过程和总结一起查，识别削减潜在风险、偏差、有害内容。奖励信号加多样数据分布整合下来，最终模型在推理上不掉队，有用性和无害性也立住了。

四个阶段走完，我的模型从"能算"到"会说"再到"懂事"：冷启动打下可读性的底子，推理 RL 把本事练出来，拒绝采样 + SFT 补上通用能力，全场景 RL 最后把有用性和无害性立住。整个过程基本复刻了 DeepSeek-R1 的节奏，也验证了冷启动确实比裸奔 RL 更稳。

## 4 讨论

实验做完了，回头看看哪些划算、哪些是坑。除了蒸馏和 RL 的对比，还有两条没走通的路也值得记一笔，都是实打实的教训。

### 4.1 蒸馏 vs 强化学习：谁更划算

从蒸馏结果看，小模型从 R1 蒸馏后成绩相当亮眼。但有个问题一直悬着：不蒸馏，光靠大规模 RL 训练，小模型能不能达到可比性能？如果答案是"能"，蒸馏这条捷径的分量就要重新掂量；如果答案是"不能"，蒸馏的性价比就更坐实了。

实验回答得很干脆：对 Qwen-32B-Base 做大规模 RL，性能只能和 QwQ-32B-Preview 相当；而从 DeepSeek-R1 蒸馏出的 32B 模型，在所有基准上都显著优于 RL 路线，对比结果见下图。也就是说，同样 32B 的底座，RL 练到头也就和当时的开源 SOTA 打平，而蒸馏路线直接全面碾压。两个结论：第一，把强模型蒸馏进小模型，效果又好又便宜，而靠大规模 RL 硬练的小模型需要巨大算力，还不一定追得上蒸馏；第二，蒸馏经济高效，但想突破智能边界，可能还是得靠更强大的基础模型加更大规模的 RL。蒸馏能赢的底层原因，是更大的基础模型在训练中已经发现了更好的推理模式，小模型把这些模式直接继承下来，比自己从零摸索省力太多。

### 4.2 不成功的尝试

#### 过程奖励模型（PRM）

PRM 听起来很合理：不光看结果对不对，还要一步步盯过程，理论上能引导模型找到更好的推理路径（Lightman 等，2023；Uesato 等，2022；Wang 等，2023）。但懂过程的代价，是过程本身难以定义。实践里三个限制很致命：一般推理中很难明确定义细粒度步骤，步骤切到多细算合适？判断中间步骤对不对更是苦差事，自动标注效果差、人工标注不可扩展；一旦引入基于模型的 PRM，奖励黑客问题就不可避免（Gao 等，2022），重训奖励模型还要额外资源和复杂度。结论：PRM 对 top-N 响应重排或辅助搜索有点用（Snell 等，2024），但相比它在大规模 RL 里引入的额外计算开销，优势有限，不如把钱花在刀刃上。

#### 蒙特卡洛树搜索（MCTS）

受 AlphaGo（Silver 等，2017b）和 AlphaZero（Silver 等，2017a）启发，我试过用 MCTS 增强测试时计算——把答案拆成小块，让模型像下棋一样系统地探索解空间。具体做法是提示模型生成多个标签，对应搜索所需的推理步骤；训练时先用预训练价值模型引导的 MCTS 找到答案，再用得到的问答对训练行动模型和价值模型，迭代完善整个流程。

但扩展训练时撞上两堵墙：token 生成的搜索空间比棋类大指数级——棋盘的格子是有限的，token 序列几乎是无限的，为了兜底给每个节点设了最大扩展限制，结果又容易陷进局部最优；价值模型直接影响生成质量，而训练一个细粒度价值模型本身极难，迭代改进也就无从谈起。AlphaGo 的成功依赖价值模型逐步提升，但在 token 生成这种场景下很难复刻。结论：MCTS 配预训练价值模型能在推理时提性能，但靠自我搜索迭代提升模型，仍是重大挑战。

---

整体来看，量化 + 蒸馏 + RL 这条路线，是我目前能找到的"低成本 + 强推理"平衡点。蒸馏负责性价比，RL 负责上限，量化负责部署落地——三个工具各管一段，这就是我的优化框架的完整拼图。过程中 PRM 和 MCTS 都试过、都踩了坑，但这反而让我更清楚哪条路值得走。这套组合拳也为 LLM 的高效部署和应用提供了新的思路。路还长，但至少方向是亮的。
