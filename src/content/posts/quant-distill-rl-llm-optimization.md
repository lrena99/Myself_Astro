# 量化 + 蒸馏 + 强化学习：我的 LLM 优化研究笔记

这篇是我的研究笔记，主题一句话：把量化、蒸馏和强化学习（RL）组合起来，在不大幅牺牲性能的前提下，把大模型的推理能力和效率都提上去。量化砍掉存储和计算成本，蒸馏把大模型的知识搬进小模型，再用大规模 RL 训练让它在复杂任务里更能打。我自己的实验观察是，量化蒸馏后的模型在推理任务上能和原始大模型掰手腕，同时计算资源消耗少一大截；而 RL 的加入，又让它在复杂推理和多任务场景里更上一层楼。

## 1 为什么做这件事

2024 年，OpenAI、Anthropic、谷歌这些机构在 LLM 上一路狂奔，AGI 似乎越来越近。在这个背景下，后训练成了训练流程里不可或缺的一环——花更少的计算资源，把推理准确率提上去，还让模型跟社会价值观对齐、贴合用户偏好。

OpenAI 的 o1 系列靠拉长思维链（CoT）引入了"推理时间扩展"，在数学、编码、科学推理上进步明显。但怎么做好测试时扩展，至今还是研究界的大难题：过程奖励模型、强化学习、搜索算法都有人试过，可没有一个达到 o1 级别的通用推理性能。

转折点是 DeepSeek。他们用纯 RL 训练 DeepSeek-V3-Base，以 GRPO 为框架，在完全没有监督数据的情况下让模型自己长出推理能力。几千步 RL 之后，DeepSeek-R1-Zero 在推理基准上追平了 OpenAI-o1-0912。代价也很真实：可读性差、语言混杂，输出经常没法看。

于是 DeepSeek 又推出了 R1：先用几千条冷启动数据微调 base 模型，再做面向推理的 RL；RL 快收敛时用拒绝采样造新的 SFT 数据，混合多领域监督数据重新训练。最后得到的检查点性能对齐 OpenAI-o1-1217。他们还尝试把 R1 蒸馏进小模型——用 Qwen2.5-32B 做底座直接蒸馏，效果居然好过在它身上跑 RL。蒸馏出的 14B 模型比当时的开源 SOTA QwQ-32B-Preview 还强，32B 和 70B 直接刷新了密集模型推理基准的纪录。

总结下来就是：纯 RL 能解锁推理能力，但伴随可读性差、语言混杂的问题；蒸馏则是把小模型"喂大"的性价比路线。我接下来的研究，就是基于量化和蒸馏的强化学习优化技术，到底怎么落地。

## 2 方法

### 2.1 强化学习算法：GRPO

组相对策略优化（GRPO）的核心思想，是用一组采样输出来估计基线，这样就不需要和策略模型一样大的 critic 模型了。对每个问题，从旧策略采样一组输出，然后优化策略模型：

- **目标函数**：最小化策略模型与旧策略的比率乘奖励，加上 KL 散度正则项；
- **KL 散度**：衡量当前策略和参考策略差多远，防止模型跑飞；
- **优势计算**：用每组输出的奖励做标准化，让奖励分布更稳定。

![截图](/images/posts/quant-distill-rl-llm-optimization/01.webp)

### 2.2 奖励模型

两条奖励线：

- **准确性奖励**：看回答对不对。数学这种有确定答案的问题，要求模型把最终答案放进特定格式（比如框起来）方便验证；编程题就让编译器按预定义测试用例给反馈；
- **格式奖励**：要求模型把思考过程包在特定标签里（比如 `<think>` 和 `</think>`），规范输出格式。

### 2.3 训练模板

一个简单的模板，让模型先输出推理过程再给答案：

```text
User: prompt
Assistant: <think>推理过程</think><answer>答案</answer>
```

训练时把具体问题替换进 `prompt` 就行。

### 2.4 带冷启动的强化学习

**冷启动**：先收集少量长链推理数据微调基础模型，作为 RL 的起点。生成冷启动数据有三种路子：用长 CoT 示例做少样本提示；直接让模型生成带反思和验证的详细答案；收集模型输出后人工标注后处理。目标是提高可读性和推理能力——设计"推理过程 + 总结"的可读格式，过滤掉不合格输出。

**推理导向 RL**：在冷启动微调后的模型上，用和 R1-Zero 一样的 RL 流程，专攻编程、数学、科学、逻辑推理。针对语言混合问题引入语言一致性奖励——统计思维链里目标语言词的比例，和准确性奖励相加作为最终奖励。代价是消融实验显示性能会略降，但对话可读性符合人类偏好，值。

**拒绝采样 + SFT**：RL 收敛后，用拒绝采样从 checkpoint 生成推理提示和轨迹扩数据集，过滤掉语言混合、超长段落、代码块，只留正确输出；非推理任务（写作、事实问答、自我认知、翻译）用自动数据生成加复用已有的 SFT 数据集。最后约 800k 样本，对基础模型做两轮微调。

**全场景 RL**：组合奖励信号加多样化提示分布。推理数据用规则化奖励引导数学、编程、逻辑；通用数据用奖励模型捕捉复杂场景的人类偏好。安全性上全面评估输出——推理过程和总结都查，识别并削减风险、偏见、有害内容。

### 2.5 蒸馏：给小模型开外挂

生成 800k 样本直接对开源小模型做 SFT，把推理能力迁移过去。基础模型选 Qwen2.5-Math 系列（1.5B / 7B / 14B / 32B）、Llama-3.1-8B、Llama-3.3-70B-Instruct（3.3 的推理略强于 3.1）。只做 SFT 不加 RL——这样才能干净地展示蒸馏本身的效果。

## 3 我的实操：四阶段复现 DeepSeek-R1 思路

受 R1-Zero 启发，我在实际场景里遇到两个真问题：其一，能不能用少量高质量数据做冷启动，进一步提升推理性能或加快收敛？其二，怎么训练出一个既能生成清晰连贯思维链、又有强大通用能力的用户友好型模型？参考 DeepSeek-R1 的流程，我设计了四个阶段。

**冷启动**：和 R1-Zero 不同，我担心 RL 在基础模型早期冷启动阶段不稳定，所以先收集少量长思维链数据微调，作为初始 RL 智能体。收集手段试了好几种：长 CoT 示例少样本提示、直接让模型生成反思验证过的详细答案、用可读格式收集输出再人工后处理。最终收集了几千条冷启动数据，微调 base 模型。对比下来，冷启动有两个明显优势：

- **可读性**：R1-Zero 的输出经常混着多种语言、缺 Markdown 格式，用户根本没法看。我的冷启动数据设计成"推理过程 + 总结"的结构化格式，每个回复结尾有总结，过滤掉难读的回复；
- **潜力**：结合人类先验精心设计冷启动模式，实测性能优于 R1-Zero 路线，推理能力显著提升。迭代式训练对推理模型来说确实是更优解。

**面向推理的 RL**：在冷启动微调后的模型上跑大规模 RL，聚焦编码、数学、科学、逻辑推理。训练中观察到思维链经常语言混合（尤其提示词多语言时），于是引入语言一致性奖励——思维链中目标语言词的比例。消融显示性能略降，但符合人类偏好、内容更可读。最终奖励 = 推理准确性 + 语言一致性奖励，训到收敛为止。

**拒绝采样 + SFT**：RL 收敛后，用 checkpoint 收集下一轮的 SFT 数据。这一阶段和冷启动不同，必须纳入其他领域数据来提升写作、角色扮演等通用能力。推理数据通过拒绝采样生成轨迹，用规则奖励评估的照旧，另外扩展了用生成式奖励模型判别的数据——把真实值和模型预测喂给大模型判断；同时过滤语言混合、长段落、代码块，每个提示采样多个回复只留对的。非推理数据复用大模型的 SFT 流程，简单的查询（比如"你好"）不生成思维链。

**全场景 RL**：第二阶段 RL 主打有用性和无害性，同时保持推理能力。推理数据用规则化奖励引导数学、代码、逻辑；通用数据用奖励模型抓人类偏好。有用性评估只看最终总结，避免干扰底层推理；无害性评估整个回复——推理过程和总结一起查，识别削减潜在风险、偏差、有害内容。最终模型在推理上不掉队，有用性和无害性也立住了。

## 4 讨论

### 4.1 蒸馏 vs 强化学习：谁更划算

从蒸馏结果看，小模型从 R1 蒸馏后成绩相当亮眼。但有个问题一直悬着：不蒸馏，光靠大规模 RL 训练，小模型能不能达到可比性能？

实验回答得很干脆：对 Qwen-32B-Base 做大规模 RL，性能只能和 QwQ-32B-Preview 相当；而从 DeepSeek-R1 蒸馏出的 32B 模型，在所有基准上都显著优于 RL 路线。两个结论：第一，把强模型蒸馏进小模型，效果又好又便宜，而靠大规模 RL 硬练的小模型需要巨大算力，还不一定追得上蒸馏；第二，蒸馏经济高效，但想突破智能边界，可能还是得靠更强大的基础模型加更大规模的 RL。

### 4.2 不成功的尝试

**过程奖励模型（PRM）**：PRM 理论上能引导模型找到更好的推理路径，但实践里三个限制很致命：一般推理中很难明确定义细粒度步骤；判断中间步骤对不对是苦差事，自动标注效果差、人工标注不可扩展；一旦引入基于模型的 PRM，奖励黑客问题就不可避免，重训奖励模型还要额外资源和复杂度。结论：PRM 对 top-N 响应重排或辅助搜索有点用，但相比它在大规模 RL 里引入的额外计算开销，优势有限。

**蒙特卡洛树搜索（MCTS）**：受 AlphaGo 启发，我试过用 MCTS 增强测试时计算——把答案拆成小块，让模型系统探索解空间。但扩展训练时撞上两堵墙：token 生成的搜索空间比棋类大指数级，设最大扩展限制又容易陷进局部最优；价值模型直接影响生成质量，而训练一个细粒度价值模型本身极难，迭代改进也就无从谈起。AlphaGo 的成功依赖价值模型逐步提升，但在 token 生成这种场景下很难复刻。结论：MCTS 配预训练价值模型能在推理时提性能，但靠自我搜索迭代提升模型，仍是重大挑战。

---

整体来看，量化 + 蒸馏 + RL 这条路线，是我目前能找到的"低成本 + 强推理"平衡点。蒸馏负责性价比，RL 负责上限，量化负责部署落地——三个工具各管一段，这就是我的优化框架的完整拼图。
